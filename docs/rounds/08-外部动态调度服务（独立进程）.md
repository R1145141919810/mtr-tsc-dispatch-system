# 08 · 外部动态调度服务（MTR 4 / TSC，独立进程）

本文描述一个**完全独立于游戏进程**的调度服务：不改 MTR/TSC 源码，不链接任何游戏类，只通过 HTTP 与运行中的
服务器交互，实时读取状态、动态计算进路、下发调度指令。

交付物：

| 路径 | 说明 |
|---|---|
| `tsc-dispatch/` | 完整工程（40 个源文件，零第三方依赖，Java 17） |
| `tsc-dispatch/build/tsc-dispatch-1.0.0.jar` | 可直接运行的 jar（149 KB），`java -jar ... run` |
| `tsc-dispatch/build.ps1` / `build.gradle` | 两条等价构建路径 |
| `tsc-dispatch/docs/bridge-protocol-v1.md` | 控制桥协议 v1（写通道契约） |
| `docs/08-外部动态调度服务（独立进程）.md` | 本文 |

本机实测（见 §5）：构建通过，自检 **25/25** 断言通过；对内置 TSC 替身服务器完整跑通“读状态 → 算路径 →
下发选台指令 → 车辆改台 → 不重复下发”闭环。

## 1. API 能力调研与边界确认

### 1.1 取证方式

结论不是从文档抄的，而是逐条对齐实现：

1. 读 MTR 4 服务端源码，确认它以什么参数启动 TSC、注册了哪些 servlet；
2. 读 TSC 的 `Main` / `SystemMapServlet` / `OBAServlet` / `ServletBase` / `OperationProcessor` 实现；
3. 在**发布版 jar**（Forge 1.20.1 构建）里核对 `org/mtr/core/servlet/*.class` 的实际清单，
   排除“源码里有、发布版没有”的情况；
4. 用内置 mock 服务器按真实报文形状回放，验证解析逻辑（空字段、缓存、十六进制 id、包封信封）。

### 1.2 HTTP 面到底有什么

TSC 的 HTTP 服务器只在启动时注册**三个** servlet，没有第四个：

| 路径 | 实现 | 作用 |
|---|---|---|
| `/` | `WebServlet` | 内嵌 Angular 看板静态资源 |
| `/mtr/api/map/*` | `SystemMapServlet` | 系统地图 / 到站数据 |
| `/oba/api/where/*` | `OBAServlet` | OneBusAway 兼容层（大量桩实现） |

MTR 4 在服务端启动时用配置项 `server.webserverPort`（`config/mtr.json`，默认 8888）拉起这套服务器；
若端口被占用，会**改用空闲端口**，这是必须注意的部署细节（见 §6）。

`/mtr/api/map/*` 实际可用端点：

| 端点 | 缓存 | 返回内容 |
|---|---|---|
| `stations-and-routes` | 30 s（服务端） | 车站列表（hex id、名称、颜色、zone、连通站）、线路列表（hex id、名称、编号、颜色、类型、环形方向、**按站序排列的停靠站**、每段计划运行时长、所属车厂**名称**） |
| `departures` | 3 s | `线路hex → [ {deviation, departures:[相对当前时刻的毫秒数]} ]`，是**终点站发车看板**，不是车辆位置 |
| `arrivals` | 无（按请求计算） | 指定站/台的一批到达预测：`platformId`、`platformName`、`routeId`、`arrival`、`departure`、`deviation`、`departureIndex`、`isTerminating`、`cars[{vehicleId, capacity, passengerCount}]` |
| `clients` | 3 s | 在线玩家坐标、所在站；若在乘车则附当前/下一线路与车站 |
| `directions` | 队列 | 乘客换乘寻路，不是列车进路 |

`/oba/api/where/*` 只实现了 5 个端点（`agencies-with-coverage`、`agency`、
`arrivals-and-departures-for-stop`、`stops-for-location`、`trip-details`）；其余 20 余个——
**包括 `vehicles-for-agency` 和 `trip-for-vehicle`**——是返回 `{}` 的桩，不能依赖。

### 1.3 能拿到 / 拿不到

| 需要的数据 | 原版 HTTP | 说明 |
|---|---|---|
| 车站、线路、站序、站间计划时长、停站时长 | ✅ 直接支持 | `stations-and-routes`，30 s 缓存，适合做静态拓扑 |
| 车厂名称、线路→车厂归属 | ✅ 直接支持 | 只有名称，没有 id、没有股道、没有坐标 |
| 站台级到达预测（ETA、晚点、载客、车辆 id） | ✅ 直接支持 | 车辆 id 来自 `cars[].vehicleId`，是原版 HTTP 面上**唯一**的车辆标识 |
| 站台→车站归属 | ⚠️ 需轮询模拟 | `stations-and-routes` 不含平台 id，只能“每站查询 arrivals”反推 |
| 车辆实时位置、速度、`railProgress`、当前进路 | ❌ 不支持 | 只存在于 `get_data` / `dynamic_data_response` 的**数据包**通道 |
| 轨道占用、信号闭塞（按颜色的 `preBlockedSignalColors`） | ❌ 不支持 | 同属数据包通道 |
| 侧线 / 车场股道状态、停放车辆 | ❌ 不支持 | 同上 |
| 事件订阅 / SSE / WebSocket / 长轮询 | ❌ 不支持 | HTTP 面全是请求-响应，无推送 |
| 下发路径 / 改目标 / 指定站台 / 回场 | ❌ 不支持 | HTTP 面**没有任何写入口** |
| 鉴权 | ❌ 无 | 服务器无 token，CORS 为 `*` |

**结论：MTR 4 自带的 HTTP 面是“只读 + 站台级”的。**
这不是文档缺漏，而是架构事实：写操作协议 `get_data` / `update_data` / `delete_data` / `list_data` /
`arrivals` / `block_rails` / `generate_by_depot_*` / `clear_by_depot_*` / `instant_deploy_by_depot_*`
全部由 `OperationProcessor` 分派，而它只被**客户端↔服务端的数据包管线**调用，
没有任何 servlet 把 HTTP 请求转发到它。

### 1.4 写通道：现实与三条降级路线

| 路线 | 能力 | 前提 | 本服务的实现 |
|---|---|---|---|
| A. 纯观察（默认可用） | 计算并记录决策，不落地 | 无 | `DryRunActuator`，决策状态 `ADVISORY` |
| B. RCON + 控制台命令 | 粗粒度：按车厂重生成路径 / 立即投放 / 清空 | 服务器开启 RCON | `RconActuator`（自实现 Source RCON 协议），映射到 `mtr generatePath` / `mtr instantDeploy` / `mtr clearVehicles <车厂名>` |
| C. 控制桥（细粒度） | 逐车：选台 / 绕行 / 压车 / 回场 | 部署一个能落到车上的桥 | `BridgeActuator`，协议见 `tsc-dispatch/docs/bridge-protocol-v1.md` |

路线 C 的桥**不需要**改 MTR/TSC：TSC 在 `Main` 构造函数里预留了 `additionalWebserverSetup` 扩展点
（三个内置 servlet 注册完、`start()` 之前触发），任何宿主（含模组）都可以在启动前追加自己的 servlet；
桥也可以直接调用 TSC 公开的 `OperationProcessor.process(key, data, simulator)` 把 `update_data` 落进模拟器。
本服务只认协议，不认实现——桥是“谁写都行”的契约。

### 1.5 与本工作区已有附属模组的关系

工作区里另有一个独立开发的附属模组（限速判定 / 信号隔离 / 车厂优化）。它**没有**面向外部进程的接口：

- 没有 HTTP 端口、没有管理命令、没有脚本入口；
- 对外只有若干 `public final class`（交通快照注册表、动态占用、评估器等），属于**编译期强耦合**，
  没有版本契约、没有 SPI、没有事件总线；
- 它的入口是游戏内界面，不是可编程接口。

因此本服务**不依赖**它，也不把任何能力建立在它之上：§1.4 的 A/B/C 三条路线与“有没有附属模组”完全正交。
若将来要复用它的车内数据，正确做法是让它在服务端开一条符合 §1.4-C 协议的桥，
而不是让外部进程反编译或反射它的内部类。

### 1.6 能力矩阵

| 能力 | 判定 |
|---|---|
| 拓扑、站序、计划时长、车厂归属 | **直接支持** |
| 站台到达预测、晚点、载客、车辆 id | **直接支持** |
| 站台占用推断 | **轮询模拟**（到达预测的时间窗重叠） |
| 车站容量 / 可用站台集合 | **轮询模拟** + 平台目录兜底（§6） |
| 车辆位置、速度、信号闭塞 | **当前不支持** → 桥 |
| 逐车改道 / 选台 / 回场 | **当前不支持** → 桥；否则 advisory |
| 车厂路径重生成 | **降级支持** → RCON |
| 事件驱动（低于轮询延迟） | **不支持** → 2 s 轮询 + 幂等 + 前置条件 |

### 2.2 模块职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 采集 | `source/StockTscSource`、`source/BridgeSource`、`source/HttpJson` | 轮询、解包信封、容错解析、平台发现；统一超时/重试/5xx 退避 |

| 冲突 | `dispatch/LeaseTable` | 资源租约，支持过期 / 抢占（更早到达者优先） |
| 下发 | `dispatch/CommandBus` | 幂等、序号、前置条件、重试、日志、状态落盘 |
| 执行器 | `actuator/*` | 能力自述 + 三种实现 |
| 持久化 | `persist/StateStore` | 原子状态文件 + 追加式 `commands.jsonl` 审计日志 |
| 观测 | `admin/AdminServer`、`util/Metrics`、`util/Log` | 管理 API、看板、Prometheus 指标、结构化日志 |

### 2.3 并发与不变量

- **单写者**：轮询线程是唯一写世界模型、唯一触发决策的线程；管理 API 只读快照、只写配置覆盖。
- **快照不可变**：决策期间世界模型不被修改，避免“边算边变”。
- **顺序**：`sequence` 单调递增并持久化；同一车辆同一触发类型的幂等键含“分钟桶”，重启后同分钟内不会重发。
- **不变量**：
  1. 指令只在其前置条件（车辆当前站台）与最新快照一致时才发送；
  2. 同一资源（站台/车厂）同时只有一个租约持有者；
  3. 指令必须带 TTL，过期即丢弃，绝不“补发”；
  4. 执行失败必须释放该车辆的所有租约。

### 2.4 降级矩阵

| 场景 | 遥测源 | 执行器 | 决策结果 |
|---|---|---|---|
| 桥可用 | `tsc-control-bridge` | `bridge` | `APPLIED` / `ACCEPTED` |
| 原版 HTTP + RCON | `tsc-stock-http` | `rcon` | 选台/绕行 → `ADVISORY`；车厂重生成 → `ACCEPTED` |
| 仅原版 HTTP | `tsc-stock-http` | `dry-run` | 全部 `ADVISORY`（可在看板/日志消费） |
| TSC 离线 | 上一次快照 | 不变 | 健康降级 `DEGRADED/FAILING`，管理面照常可用 |

## 3. 关键流程

### 3.1 进站前动态选台

触发：车辆有下一站台预测，且该站台在 `[now-5s, eta+headway]` 窗口内被**更早到达**的车辆或本服务租约占用。

```text
每 2 s:
  snapshot  ← poll()
  occupancy ← Occupancy.from(snapshot) + overlayLeases()
  for station in groupBy(vehicles, stationHex):
      claimed ← {}
      for v in sortBy(eta):
          desired ← v.platformHex
          if desired ∈ claimed  or  busyByEarlierOrLease(desired, v):
              choice ← PlatformSelector.select(v, claimed)
              chosen ← choice.changed ? choice.platform : desired
          else:
              chosen ← desired
          claimed.add(chosen)
          if chosen ≠ desired and cooldown(v, PLATFORM_SELECTION):
              if lease.tryAcquire("platform:"+chosen, v, ttl, priority = v.eta):
                  emit SET_PLATFORM {stationId, platformId = chosen, previousPlatformId = desired}
```

三条判定保证“先到先得、后车让行、结果可复现”：

1. **claimed 集合**处理 ETA 相同或极近的情况（按 eta 排序后，先处理者先占）；
2. **更早到达者优先**：只有 `slot.busyFrom < eta - 5s` 才算“别人先占了”，否则不把自己赶走；
3. **租约**：本服务自己发出的占用一律视为硬冲突（`slot.lease` 短路），避免两轮决策把同一站台发给两列车。

下发前 `CommandBus` 还会复核 `v.platformHex` 是否仍等于 `previousPlatformId`；不符则 `SKIPPED(stale)`，
不会把过期决策砸到已经开走的车上。

### 3.2 岔路口前动态重规划

关键点：**列车不是可自由选路的数据包**，它已经承诺了下一站。所以比较的不是“从当前站到目标的最短路”，
而是 **“按承诺走，并在下一站等” vs “在岔路口改走替代径路”**：

```text
for v where 0 < (eta - now) ≤ lead:
    route ← routes[v.routeHex];  i ← route.indexOf(v.station)
    next ← route.stops[i+1];     target ← route.stops[i+2]
    if freeAt(next, eta) ≤ eta + 15s: continue            # 前方不挤，无需干预
    committed ← cheapestEdge(v.station → next)
    costStay  ← edgeCost(committed, eta) + plan(next → target).cost   # 含在 next 的等待惩罚
    costAlt   ← plan(v.station → target, avoid = {next}).cost
    if plan_reached and costAlt + 30 < costStay:
        emit REROUTE {targetStationId = target, avoidStationId = next, via = ..., planCost}
```

代价函数（单位：等效秒，权重全部可配）：

```text
edgeCost(e, t) = travelSeconds(e)                * w.travel
               + max(0, freeAt(e.to, t) - t)/1000 * w.wait
               + (busy ? min(900, 60 + waitSeconds) : 0) * w.occupancy
               + (e.to ∈ avoid ? 900 : 0)
               + (e.to 是车厂 ? travelSeconds(e) * (w.depot - 1) : 0)
```

“占用惩罚上限 900 s + 绕行惩罚有限”是刻意设计：**任何情况下都要能给出一个可行解**，
而不是 `Infinity` 导致规划器返回空、服务卡死。

### 3.3 定时返回中间车场

```text
for v in vehicles:
    if v.inDepot: continue
    elapsed ← now - (v.serviceStart ?: firstSeen[v])
    if elapsed < budget and not inWindow(return-at-local-time): continue
    if cooldown(v, RETURN_TO_DEPOT, 10 min): continue
    terminus ← (route.indexOf(v.station) == route.stops.size - 1)
    if v.atPlatform and not terminus and v.passengers > 0:
        emit ADVISORY "deferred: passengers aboard, wait for terminus"; continue
    plan ← router.toNearestDepot(v.station, eta)
    if not plan.reached: emit ADVISORY "no reachable depot"; continue
    lease.tryAcquire("depot:"+name, v, ttl, priority = eta)
    emit RETURN_TO_DEPOT {depot, stationId}
```

边界覆盖：**正在载客**（推迟到终点站）、**正在进站/停站**（非终点站则推迟）、**已经在车场**（跳过）、
**没有可达车厂**（记录建议而不发指令）、**刚回场又触发**（10 分钟冷却）、
**时间窗**（`HH:mm-HH:mm`，支持跨零点）。

### 3.4 重启 / 断连恢复

状态文件 `state/dispatch-state.json`（原子写入：临时文件 + `ATOMIC_MOVE`）：

```json
{ "version": 1, "sequence": 42,
  "applied": [{"key": "platform|1002|...|29183", "at": 1715000000123}],
  "leases":  [{"resource": "platform:...0042", "vehicle": "1002", "expiresAt": 1715000120123}] }
```

```text
启动:
  state    ← load()                  # sequence / 幂等键 / 租约
  sequence ← state.sequence          # 序号继续递增，绝不回绕
  applied  ← {k | now - k.at < dedupWindow}
  leases.load(); leases.expire(now)
  第一轮: 全量重建世界模型（不假设任何缓存）
  对每条历史指令: 不复发，只重新评估“意图是否仍然成立”
      意图成立 且 状态未变 → 幂等键命中 → SKIPPED(duplicate)
      意图成立 但 状态已变 → 前置条件不符 → SKIPPED(stale)
      意图已失效           → 不产生任何指令
```

断连行为：轮询失败计数 +1，健康 `OK → DEGRADED`（3 个周期）→ `FAILING`（> 60 s）；
期间**继续用最后一次快照**对外服务，但决策时钟基于 `serverTimeMillis`，不会因本地时间前进而凭空触发；
恢复后第一轮全量刷新，租约按剩余 TTL 生效，失效租约在 `expire()` 中清除。

## 4. 技术选型与代码骨架

### 4.1 选型

| 关注点 | 选择 | 理由 |
|---|---|---|
| 语言/运行时 | **Java 17** | 与目标服（Forge 47.x）同代 JDK，运维无需额外运行时 |
| 依赖 | **零第三方** | 目标环境常无外网；自实现 JSON / HTTP / RCON / 指标，jar 仅 149 KB |
| HTTP 客户端 | `java.net.http.HttpClient` | JDK 内置，连接复用，超时语义清晰 |
| HTTP 服务端 | `com.sun.net.httpserver` | 只需 REST + 静态页，无需 Servlet 容器 |
| 定时任务 | `ScheduledExecutorService` | 单线程轮询足够；决策耗时 < 10 ms |
| 配置 | 扁平 `.properties` | 可直接改、可运行时覆盖、生成带注释模板 |
| 持久化 | JSON 原子写 + JSONL 追加 | 人读友好、可 `tail -f`、崩溃不产生半截文件 |
| 日志/指标 | 结构化日志 + Prometheus 文本 | 不引入日志框架，字段化便于检索 |
| 测试 | 内置 `selftest`（无 JUnit） | 交付物“拿到就能验证”，不依赖构建工具链 |

### 4.2 关键代码骨架

**幂等下发**（`dispatch/CommandBus.java`）：

```java
public void submit(Decision decision, WorldSnapshot snapshot) {
    Command c = decision.command;
    if (!actuator.supports().contains(c.kind))          { status = ADVISORY; return; }  // 能力降级
    if (now > c.expiresAtMillis)                        { status = SKIPPED;  return; }  // 过期
    if (seen(c.idempotencyKey))                         { status = SKIPPED;  return; }  // 幂等
    Vehicle v = snapshot.vehicle(c.preconditionVehicleId);
    if (v == null)                                      { status = SKIPPED;  return; }  // 车没了
    if (!c.preconditionPlatformHex.equals(v.platformHex)) { status = SKIPPED; return; } // 状态漂移

    c.seq = nextSequence();                                  // 持久化序号
    for (attempt = 1 .. maxAttempts) {
        r = actuator.execute(c);
        if (r.success || !r.retryable) break;
        sleep(backoff * 2^(attempt - 1));                     // 指数退避
    }
    if (r.success) applied.put(c.idempotencyKey, now);
    else           leases.releaseAll(c.vehicleId);            // 失败释放资源
    journal(c, decision); persist();                          // 审计 + 状态落盘
}
```

**租约与冲突**（`dispatch/LeaseTable.java`）：

```java
boolean tryAcquire(resource, vehicle, now, ttl, priorityMillis) {
    Lease e = leases.get(resource);
    if (e == null || e.vehicle.equals(vehicle) || e.expiresAt <= now) { put(); return true; }
    if (priorityMillis + 1000 < e.priorityMillis) { put(); return true; }  // 更早到达者抢占
    return false;
}
```

**时变 Dijkstra**（`plan/Router.java`）：

```java
while (!open.isEmpty()) {
    Label cur = open.poll();
    if (cur.cost > best[cur.node]) continue;
    if (cur.node.equals(target)) return reconstruct(cur);
    for (Edge e : graph.outgoing(cur.node)) {
        long arrival = cur.arrival + e.travelMillis();                     // 时间向前推进
        double cost  = cur.cost + costModel.edgeCost(e, cur.arrival, ctx); // 按出发时刻计价
        if (cost < best[e.to]) relax();
    }
}
```

RCON `actuator/RconClient`、管理 API `admin/AdminServer`。

## 6. 风险与兼容性

| 风险 | 影响 | 缓解 |
|---|---|---|
| **原版 HTTP 无写通道**（最大风险） | 无法真正改变列车行为 | 三档降级（§1.4）；先把决策跑对，再按需接桥 |
| 车辆级遥测缺失 | 无法做信号闭塞级避让 | 站台级模型 + 桥 |
| 轮询延迟（2 s）与服务端缓存（arrivals 0 s / departures 3 s / 拓扑 30 s） | 决策基于旧状态 | 前置条件复核、TTL、幂等键、去抖 |
| 平台发现是“需求驱动”的 | 空闲备用台可能不可见 | `catalogue.platforms` 显式声明（已实现） |
| 指令并发冲突 | 两车抢同一资源 | 租约 + 确定性排序（ETA → 名称） |
| 性能 | 每 tick 重建图 O(E) | 千级边 < 10 ms；更大规模可加拓扑版本号缓存 |
| TSC 字段/端点漂移 | 解析失败 | 全字段容错（缺失取默认）、能力探测而非版本号判断、未知端点自动降级 |
| 服务器端口被占被换 | 连不上 | 以日志/实际端口为准；`tsc.base-url` 可配 |
| 多维度 | `dimension` 索引与启动顺序绑定 | 每个维度一个实例（不同 `tsc.dimension`） |
| 无鉴权 + CORS 为 `*` | 数据暴露 | 限制服务器监听地址；服务管理面支持 `admin.token` |
| 时钟偏差 | ETA 判断偏移 | 一律使用服务器 `currentTime` / `serverTime`，本地时钟只用于计时长 |

**兼容性**：服务是外部进程，**与加载器无关**（Forge / Fabric / NeoForge 都一样，只依赖 HTTP 端口）；
对 MTR 4.0.0+ 的差异只体现在“字段有没有、端点有没有”，代码里全部按可选字段处理。
真正的行为开关是 `actuator.mode` 与桥的能力自述，升级版本不需要改代码。
